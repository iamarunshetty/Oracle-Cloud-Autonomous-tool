# Oracle Fusion Access Manager

A **Windows desktop tool** for Oracle Fusion access administration.  
Built with Python + PySide6 and packaged as a single `.exe` via PyInstaller + Inno Setup.

## Architecture Overview

```
main.py                      ← Desktop entry point (PySide6 QApplication)
app/
  config.py                  ← Settings loader (.env + env vars)
  models/                    ← Dataclass domain models
    user.py | role.py | data_access.py | audit.py | report.py
  services/                  ← Business logic (stubs with TODO API hooks)
    user_service.py          ← Create/edit/enable/disable/delete/search/bulk/compare
    role_service.py          ← Assign/remove/copy/compare/history/approval
    data_access_service.py   ← Data roles, security contexts, compare
    password_service.py      ← Reset/force-change/unlock/login-status
    security_service.py      ← SoD/elevated/inactive/orphan/duplicate
    reporting_service.py     ← Excel, PDF, CSV report generation
    bulk_upload.py           ← Excel template parser & validator
    template_generator.py    ← Regenerate sample Excel templates
  storage/
    database.py              ← SQLite connection + schema (WAL mode)
    repositories.py          ← AuditRepository, OperationHistoryRepository
  ui/
    main_window.py           ← QMainWindow + 7 tabs + log panel + status bar
    tabs/                    ← One module per functional tab
      user_management.py | role_management.py | data_access.py
      password_management.py | security_analysis.py
      audit_reporting.py | job_monitor.py
    widgets/
      operation_log.py       ← Shared scrollable log panel
  security/
    secrets_provider.py      ← Abstraction over credential storage
templates/
  bulk_user_upload_template.xlsx   ← Generated by template_generator.py
tests/
  test_config.py | test_bulk_upload.py | test_audit_trail.py | test_report_export.py
```

**Key design decisions:**

- All Oracle Fusion API calls are **explicit stubs** with `# TODO` comments.  
  The architecture is ready for live integration without structural changes.
- Credentials are **never hard-coded**; they flow through `SecretsProvider`.
- SQLite is used for local audit trail and operation history.  
  The schema is auto-applied on first run.
- The UI layer only calls service methods; services own all business logic.

## Setup Instructions

### Prerequisites

- Python 3.11 or 3.12 (Windows)
- Git

### 1 – Clone and create virtual environment

```bash
git clone https://github.com/iamarunshetty/Oracle-Cloud-Autonomous-tool.git
cd Oracle-Cloud-Autonomous-tool

python -m venv .venv
# Windows:
.venv\Scripts\activate
# Linux / macOS:
source .venv/bin/activate
```

### 2 – Install dependencies

```bash
pip install -r requirements.txt
# or
make install
```

### 3 – Configure environment

```bash
cp .env.example .env
```

Edit `.env` and set at minimum:

```env
FUSION_BASE_URL=https://your-tenant.oraclecloud.com
```

Credentials for Oracle Fusion are loaded by `SecretsProvider`.  
See [Security Notes](#security-notes) for how to wire Windows Credential Manager.

### 4 – Generate Excel templates (first time)

```bash
python -m app.services.template_generator
# or
make templates
```

## Running the Application

```bash
python main.py
# or
make run
```

The database file `fusion_tool.db` is created automatically on first run.

## Build EXE (PyInstaller)

```bash
pip install pyinstaller
pyinstaller --noconfirm FusionAccessManager.spec
# or
make build-exe
```

The single-file executable is written to `dist/FusionAccessManager.exe`.

> **Tip:** The `FusionAccessManager.spec` file is pre-configured for a
> windowed (no console), one-file build.  Edit `icon=` to set a custom
> `.ico` file.

---

## Create Installer (Inno Setup)

1. Install [Inno Setup](https://jrsoftware.org/isinfo.php) on Windows.
2. Build the EXE first (see above).
3. Run:

```cmd
ISCC installer.iss
```

The installer `FusionAccessManagerSetup.exe` will be created in the current
directory.  It includes the EXE, `.env.example`, and Excel templates.

## Developer Notes – Oracle Fusion API Integration

All service files contain explicit `# TODO` comments marking the exact
API call to implement.  The pattern is:

```python
def create_user(self, user: User, performed_by: str = "system") -> User:
    """
    TODO: POST /hcmRestApi/resources/11.13.18.05/userAccounts
    Headers: Authorization: Basic <base64(username:password)>
    Body: {"Username": ..., "PersonId": ...}
    """
    # --- stub ---
    _USERS[user.username] = user
    ...
```

### REST base URL

```
settings.fusion_base_url  (from .env → FUSION_BASE_URL)
```

### Authentication

Retrieve credentials via:

```python
from app.security.secrets_provider import secrets
password = secrets.get_credential("fusion-password")
```

### Key Fusion API families

| Domain | Endpoint family |
|---|---|
| User Accounts | `/hcmRestApi/resources/11.13.18.05/userAccounts` |
| Roles | `/fscmRestApi/resources/11.13.18.05/roles` |
| Data Security | `/fscmRestApi/resources/11.13.18.05/dataSecurityPolicies` |
| Identity (IDM) | `/idm/v1/users/{username}/*` |
| Workflow/AME | Oracle BPM Workflow REST API |

## Security Notes

- **Never commit** the `.env` file (it is in `.gitignore`).
- The `SecretsProvider` abstraction in `app/security/secrets_provider.py`
  currently reads from environment variables (`EnvSecretsProvider`).
- To use **Windows Credential Manager**, uncomment the
  `WindowsCredentialProvider` class in that file and install `pywin32`.
- Always run the application with least-privilege Windows user accounts.
- The audit trail (`audit_events` table) records every UI-triggered action.
