## 1. User Model

**Source:** `app/models/user.py` → `User`

The `User` dataclass is the central domain object for a person account in
Oracle Fusion.

| Field | Type | Required | Description |
|---|---|---|---|
| `username` | `str` | ✅ | Oracle Fusion login name (unique key) |
| `first_name` | `str` | ✅ | Given name |
| `last_name` | `str` | ✅ | Family name |
| `email` | `str` | ✅ | Work email address |
| `status` | `UserStatus` | — | Account status (default: `Active`) |
| `person_number` | `str \| None` | — | Oracle HCM person number |
| `department` | `str \| None` | — | Business unit / department |
| `job_title` | `str \| None` | — | Job title |
| `manager_username` | `str \| None` | — | Username of the direct manager |
| `start_date` | `datetime \| None` | — | Account activation date |
| `end_date` | `datetime \| None` | — | Account termination date |
| `last_login` | `datetime \| None` | — | Last successful login timestamp |
| `fusion_person_id` | `str \| None` | — | Oracle Fusion internal person ID (set after sync) |
| `created_at` | `datetime` | — | Record creation time (UTC, auto-set) |
| `updated_at` | `datetime` | — | Last update time (UTC, auto-set) |

**Computed properties:**

| Property | Returns | Description |
|---|---|---|
| `full_name` | `str` | `"{first_name} {last_name}"` |
| `is_active` | `bool` | `True` when `status == UserStatus.ACTIVE` |

## 2. User Status Values

**Source:** `app/models/user.py` → `UserStatus`

| Value | String | Meaning |
|---|---|---|
| `UserStatus.ACTIVE` | `"Active"` | Account is enabled and can log in |
| `UserStatus.INACTIVE` | `"Inactive"` | Account is disabled; login blocked |
| `UserStatus.SUSPENDED` | `"Suspended"` | Temporarily suspended by an administrator |
| `UserStatus.PENDING` | `"Pending"` | Account created but not yet activated |

## 3. Service Operations

**Source:** `app/services/user_service.py` → `UserService`

All methods are available via the module-level singleton:

```python
from app.services.user_service import user_service
```

Every mutating method accepts a `performed_by` parameter (defaults to
`"system"`) that is written to the audit trail.

---

### 3.1 Create User

```python
user_service.create_user(user: User, performed_by: str = "system") -> User
```

Creates a new Oracle Fusion user account.

**Parameters:**

| Parameter | Type | Description |
|---|---|---|
| `user` | `User` | Fully populated `User` object |
| `performed_by` | `str` | Username of the administrator performing the action |

**Returns:** The same `User` object (augmented with any server-assigned IDs
once live API integration is in place).

**Example:**

```python
from app.models.user import User
from app.services.user_service import user_service

new_user = User(
    username="jdoe",
    first_name="John",
    last_name="Doe",
    email="john.doe@example.com",
    department="Finance",
    job_title="Financial Analyst",
)
created = user_service.create_user(new_user, performed_by="admin")
print(created.full_name)  # John Doe
```

**Oracle Fusion API (TODO):**

### 3.2 Edit User

```python
user_service.edit_user(
    username: str,
    updates: dict,
    performed_by: str = "system",
) -> User | None
```

Updates one or more fields of an existing user.

**Parameters:**

| Parameter | Type | Description |
|---|---|---|
| `username` | `str` | The user to update |
| `updates` | `dict` | Dict of field names → new values (any `User` field) |
| `performed_by` | `str` | Auditing username |

**Returns:** Updated `User` object, or `None` if the user was not found.

**Example:**

```python
user_service.edit_user(
    "jdoe",
    updates={"job_title": "Senior Financial Analyst", "department": "Finance"},
    performed_by="admin",
)
```

**Oracle Fusion API (TODO):**
```
PATCH /hcmRestApi/resources/11.13.18.05/userAccounts/<id>
```

### 3.9 Compare Users

```python
user_service.compare_users(username_a: str, username_b: str) -> dict
```

Returns a field-by-field difference between two users.

**Compared fields:** `email`, `department`, `job_title`, `status`,
`manager_username`.

**Returns:** Dict where each key is a differing field name and the value is
`{"user_a": <value>, "user_b": <value>}`. Fields that are identical are
omitted.

**Example:**

```python
diff = user_service.compare_users("jdoe", "jsmith")
# { "department": {"user_a": "Finance", "user_b": "HR"} }
```

## 4. Bulk User Upload

### 4.1 Excel Template

Generate the template file (first time, or to reset it):

```bash
python -m app.services.template_generator
# or
make templates
```

This creates `templates/bulk_user_upload_template.xlsx`.

**Sheet columns:**

| Column | Required | Format / Notes |
|---|---|---|
| `username` | ✅ | Alphanumeric; must be unique in Oracle Fusion |
| `first_name` | ✅ | Text |
| `last_name` | ✅ | Text |
| `email` | ✅ | Must be a valid email (`user@domain.tld`) |
| `department` | — | Text; matches Oracle HCM department name |
| `job_title` | — | Text |
| `manager_username` | — | Must be an existing username |

> Row 1 is the **header row** – do not modify it.  
> Data starts on **Row 2**.

---

### 4.2 Validation Rules

**Source:** `app/services/bulk_upload.py`

The parser applies the following checks:

| Check | Error message |
|---|---|
| Required columns present in header | `"Missing required column: '<col>'"` |
| `username` not blank | `"username is required"` |
| `first_name` not blank | `"first_name is required"` |
| `last_name` not blank | `"last_name is required"` |
| `email` not blank | `"email is required"` |
| `email` matches `user@domain.tld` pattern | `"email '<value>' is not valid"` |

Rows with errors are **not** sent to Oracle Fusion. Valid rows are processed
individually via `user_service.create_user()`.

---

### 4.3 Uploading via the UI

1. Go to the **User Management** tab.
2. Click **Bulk Upload**.
3. Select your filled-in Excel file → click **Open**.
4. Review the log panel:
   - ✅ Valid rows are submitted for creation.
   - ❌ Invalid rows show the row number and specific error message.
5. A summary is displayed: `"Bulk upload: N created, M failed"`.

---

### 4.4 Uploading Programmatically

```python
from app.services.bulk_upload import parse_bulk_upload
from app.services.user_service import user_service

records, file_errors = parse_bulk_upload("templates/bulk_user_upload_template.xlsx")

if file_errors:
    print("File-level errors:", file_errors)
else:
    result = user_service.bulk_upload(records, performed_by="admin")
    print(f"Created: {result['created']}, Failed: {result['failed']}")
```

## 5. Audit Events

Every user operation writes an entry to the local SQLite audit trail
(`fusion_tool.db` → `audit_events` table).

| Operation | `AuditAction` |
|---|---|
| Create user | `CREATE_USER` |
| Edit user | `EDIT_USER` |
| Enable user | `ENABLE_USER` |
| Disable user | `DISABLE_USER` |
| Delete / terminate user | `DELETE_USER` |
| Bulk upload | `BULK_UPLOAD` |

**Audit event fields:**

| Field | Description |
|---|---|
| `action` | One of the `AuditAction` values above |
| `performed_by` | Username of the administrator who triggered the action |
| `target_username` | Username of the affected user |
| `description` | Human-readable description of the operation |
| `payload` | JSON dict with extra context (e.g. `{"email": "..."}`) |
| `success` | `True` if the operation completed without error |
| `error_message` | Populated only when `success` is `False` |
| `timestamp` | UTC datetime of the event |

Audit records can be searched and exported from the **Audit & Reporting** tab.
